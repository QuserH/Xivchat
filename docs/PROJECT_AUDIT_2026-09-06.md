## 结构检查结论

当前工程不是单层“屎山”，而是两个逐步合并的体系：Android 壳层和石之家模块。主要结构风险集中在文件过大，而不是协议层耦合：

- `ShizhijiaScreens.kt` 约 530 KB
- `AetherphoneParityScreens.kt` 约 258 KB
- `PhoneModels.kt` 约 203 KB
- `CraftScreens.kt` 约 103 KB

这些文件继续整文件追加功能会提高回归风险。本轮已先完成低风险的状态/数据、搜索缓存、视觉渲染和列表组件拆分；`ShizhijiaScreens.kt` 暂不硬拆，因其路由、图片查看器、登录状态和多个发布表单交叉引用，后续应以独立功能边界配套测试后再拆。

## 性能重点

1. 列表中禁止同步读文件、解码大图和整页网络刷新；图片应继续走现有异步缓存，列表状态只更新局部项。
2. 制作清单已移除最明显的主线程 JSON 写盘点。下一步可将历史搜索、草稿和大 JSON 缓存统一迁移到同一套 IO 存储接口。
3. 远程制作仍由插件实时状态驱动；技能列表包末尾追加可选职业/三围字段，旧短帧与无效字段不会覆盖配置，详见扩展协议文档。
4. `ShizhijiaImageLoader` 仍有重试等待和大图解码路径，后续应补基于目标尺寸的采样、内存 LRU 和最大缓存策略。
